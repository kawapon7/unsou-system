# セッションが消えた話と、ログが81MBになった話（やさしい解説）

2026年9月3日 · BLACKICE（Mac mini）で起きたこと

---

## この日、何が起きたの？

朝、iPhone から Mac に話しかけて作業していたら、**会話がとつぜん見つからなくなりました**。

調べてみたら、ぜんぜん別の問題も一緒に見つかりました。**メモ帳が81MBまでふくらんでいた**のです。

この2つ、じつは**同じ1つの原因からつながっています**。順番に見ていきます。

---

## トラブル①：会話が消えた（ように見えた）

### まず結論：消えていませんでした

会話の中身は、Mac の中にぜんぶ残っていました。**なくなったのは会話そのものではなく、「つながり」のほうです。**

### たとえ話：糸電話

iPhone と Mac は、**糸電話**でつながっていると思ってください。

- **紙コップ（iPhone側）** … あなたが話しかけるところ
- **紙コップ（Mac側）** … 実際に作業をするところ
- **糸** … その2つをつなぐ通り道

あなたが iPhone に話しかけると、糸を通って Mac に届き、Mac が作業をして、また糸を通って返事が返ってきます。この糸の役目をしているのが `remote-control` というプログラムです。

### 何が起きたか

朝、**この糸が切れました**。

`remote-control` は切れてもあきらめず、「もう一回つなごう」「だめだ、もう一回」と、ずっとつなぎ直しをくり返していました。記録には「42秒つながらなかった」というメッセージが何度も残っていました。

そして、**糸が切れたままの会話は、自動的に「おしまいの箱（アーカイブ）」に片づけられます**。iPhone の画面から会話が消えたのは、このためです。

### 大事なところ

紙コップの中身（＝会話の内容）は、**Mac の中に全部残っていました**。片づけられたのは糸のほうだけです。

だから、糸をつなぎ直せば、そのまま続きから話せます。実際、今はもうつながっています。

> **消えたのではなく、片づけられただけ。**
> 中身は Mac の中に無事にありました。

---

## トラブル②：メモ帳が81MBにふくらんだ

こちらが、本当に直す必要があった問題です。

### たとえ話：パラパラ漫画

`remote-control` は、画面に**動く表示**を出します。

```
・つないでいます…
／つないでいます…
ーつないでいます…
＼つないでいます…
```

くるくる回るマークですね。パソコンの画面で見ると、**同じ場所が書きかわっているだけ**なので、1行に見えます。

ところが今回、この表示を**ファイル（メモ帳）に書き出す設定**にしていました。

すると、どうなるでしょう。

**ファイルは「上書き」ができません。書きかえるたびに、下へ下へと足されていきます。**

つまり、パラパラ漫画を「1枚ずつ全部」保存しているのと同じ状態でした。

```
画面で見ると      →  1行がくるくる回っているだけ
ファイルに書くと  →  1コマ = 1行  が どんどん積み上がる
```

### どれくらいのペースだったか

実際に測ってみました。

| 測ったこと | 結果 |
|---|---|
| 344秒（約6分）で増えた量 | 3,069行 / 237KB |
| 1秒あたり | 約9行 |
| 1日あたりに直すと | **約60MB** |
| 8日でたまっていた合計 | **81MB（123万行）** |

1秒に9行。まばたきしている間にも、どんどん足されていたわけです。

### 2つの問題

1. **ずっと増え続ける** … 止まる理由がどこにもありません
2. **大事な記録が埋もれる** … 今朝「いつ糸が切れたか」を調べようとしたとき、くるくるマークだらけで、本当の記録を探すのがとても大変でした

---

## どうやって直したか

### 選んだ方法：「写して、空にする」

いっぱいになったメモ帳を、こうします。

1. **大事なところだけ書き写す** … くるくるマークを取りのぞいて、本当の記録の最後5,000行だけを、小さく圧縮して別の場所に保存
2. **もとのメモ帳を空っぽにする** … 中身を消して0にする
3. **古い写しは捨てる** … 30個までとっておいて、それより古いものは削除

これを**1時間ごとに自動で見張って、20MBを超えていたら実行する**ようにしました。

### なぜ「ふつうのやり方」を使わなかったか

パソコンには `newsyslog` という、こういう仕事をしてくれる標準の道具があります。でも今回は**わざと使いませんでした**。

理由をたとえ話で説明します。

`newsyslog` のやり方は、**「今のノートに別の名前をつけて棚にしまい、新しいノートを机に置く」**というものです。ふつうはこれでうまくいきます。

ところが `remote-control` は、**ノートをずっと手に持ったまま書き続けている**のです。棚にしまわれても、手に持っているのは同じノートなので、**そっちに書き続けてしまいます**。机に置かれた新しいノートは、いつまでも真っ白のまま。ふくらむのは止まりません。

そこで選んだのが「写して、空にする」方式です。これは**ノートを取り上げず、開いたまま中身だけを消す**やり方なので、手に持ったままでもちゃんと効きます。

### ちゃんと効いたか確かめた

言いっぱなしにせず、実際に測って確認しました。

| 確かめたこと | 結果 |
|---|---|
| ファイルの大きさ | 81MB → **0バイト** |
| 大事な記録は残ったか | 5,000行を保存・**読めることを確認** |
| その後ちゃんと書けているか | 13KB を正常に追記 → **OK** |
| 見た目だけ0で、中身は残っていないか | 実際のディスク使用量も16K → **本当に空になった** |
| 自動実行の登録 | 正常終了（エラーなし） |
| 糸はつながったままか | **つながったまま**（iPhone は切れていない） |

最後の1つが特に大事です。**この作業のために接続を切らずに済みました。**

---

## そもそも、これは誰のせい？

正直に分けると、**半分ずつ**です。

### プログラム側にも直せるところがある

ふつうのプログラムは、「今、出す先は画面かな？ ファイルかな？」を**確かめてから**動きます。ファイルだと分かったら、くるくるマークは出しません。意味がないからです。

`remote-control` は、この確認をしていないようでした。ここは直せる余地があります。

### こちら側の事情もある

`remote-control` の説明書を読むと、これは本来**画面の前で動かす道具**として作られています。記録用には `--debug-file` という**別の専用の出し口**がちゃんと用意されていました。

```
標準の出し口  →  人間が見る画面（くるくるマーク）
--debug-file  →  記録を残す用
```

つまり、**画面用の出し口を、記録用のファイルにつないでいた**のが今回の状態です。作った人が想定していない使い方をしていたので、ふくらんだのはある意味当然の結果でした。

ただし、iPhone から使うためには常駐させる必要があったので、**この設定にしたこと自体は正しい判断です**。

## これから

### 今日やって、終わったこと

- ふくらんだメモ帳を空にした（81MB → 0）
- 1時間ごとの自動お片づけを登録した
- 今朝の切断の記録は、調べられる形で保存した

### まだ残っていること（急ぎではない）

**より正しいやり方への切りかえ**です。

画面用の出し口は捨ててしまって（`/dev/null` に流す）、記録は `--debug-file` のほうに任せる。これが本来の形です。今のやり方は「たまったゴミを定期的に捨てる」ですが、こちらは「そもそもゴミを出さない」になります。

ただし、この切りかえには **`remote-control` の再起動が必要**で、そのとき **iPhone とのつながりが一度切れます**。今つながっているものを切ることになるので、手が空いているときにやるのが安全です。

今のお片づけでふくらみは止まっているので、**急ぐ必要はありません**。

## まとめ

| | 何が起きた | どうした |
|---|---|---|
| **①会話が消えた** | 糸（接続）が切れて、会話が自動で片づけられた | 中身は無事。つなぎ直せば続きから話せる |
| **②ログが81MB** | 画面の動きを1コマずつファイルに書き続けていた | 1時間ごとの自動お片づけを導入。効果を実測で確認 |

そして今回いちばん大事なことは、たぶんこれです。

> **「消えた」と思ったものは、消えていなかった。**
> あわてて作り直す前に、まず本当になくなっているのかを確かめる。

今回、もし確かめずに「消えたから作り直そう」と動いていたら、無事に残っている記録の上に新しいものを重ねて、本当に消していたかもしれません。
