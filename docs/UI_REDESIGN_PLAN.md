## 2. デザイン原則（全画面共通）

1. **白ベース固定**: ダークモード非対応。`globals.css` のダークメディアクエリを削除し `#ffffff` / `#171717` に固定
2. **余白は機能**: カード・セクション間は詰めない。境界線より余白で区切る（borderは `zinc-100`〜`200` の最小限）
3. **タイポグラフィで優先度**: 見出し `font-semibold tracking-tight`、本文 `text-sm`、補足 `text-xs text-zinc-500`。太さと大きさの差で階層を作り、色数を増やさない
4. **色はナビゲーションのためだけに使う**: 装飾色は禁止。画面内の色 = 所属カテゴリの色 + 状態色（成功/警告/エラー）のみ
5. **フォント**: 現在 `body` が Arial 直指定。`layout.tsx` の Geist（変数定義済み）+ 日本語フォールバックに統一する

## 3. カラーシステム案

### 3-1. 大メニュー = 現行3グループをそのまま採用（推奨）

フィールドテストが今月のため、情報アーキテクチャは変えず**色だけを載せる**のが最小リスク。

| 大メニュー | 色 | Tailwindキー | 意味づけ |
|---|---|---|---|
| 日常業務 | 青 | `blue`（基準: blue-600 `#2563eb`） | 毎日触る運行・カレンダー |
| 月次・締め業務 | 緑 | `emerald`（基準: emerald-600 `#059669`） | お金の流れ（IN/OUT/承認/収支） |
| マスタ・設定 | グレー | `slate`（基準: slate-600 `#475569`） | 低頻度の管理系 |

代替案（将来検討・今回は不採用）: IN=緑／OUT=オレンジ／分析=紫 の機能ベース5分類。
メニュー再編を伴うためフィールドテスト後に判断する。

### 3-2. 階層ごとの濃淡ルール

| 階層 | 用途 | トーン |
|---|---|---|
| 大メニュー（サイドバーグループ・トップカード） | アイデンティティ | `600`（文字・アイコン・アクセントバー） |
| 中メニュー（画面・アクティブなサイドバー項目） | 選択状態 | 背景 `50`、文字 `700`、左ボーダー `600` |
| 小メニュー（タブ・ピルサブナビ） | アクティブタブ | 下線/背景 `600`、非アクティブは `zinc-500` |
| ホバー | 全階層共通 | 背景 `50` |

- **サイドバーは「アイコンのみ色」方式（2026-08-21 ユーザー確定）**: アイコンとグループ見出しのみカテゴリ色（600）、メニュー文字は zinc のまま。選択中は背景 `50` + 文字 `700`（文字を常時カテゴリ色にする案はプレビュー比較の上で不採用）
- 状態色はカテゴリ色と独立: 成功 `emerald-600`／警告 `amber-500`／エラー `red-600`（現行踏襲）
- 帳票PDF（`#pdf-print-area`）は**モノクロのまま変更しない**

### 3-3. 実装方式（Tailwind v4 対応・ステップ①で確定）

- ナビ定義は `web/src/app/admin/nav.tsx` に一元化（サイドバー・トップ画面で共用）。各 `NavGroup` の `accent` キー（`blue`/`emerald`/`slate`）がカテゴリ色
- 色クラスは同ファイルの `CATEGORY_STYLES` に**完全なクラス文字列の静的マップ**で定義する
  （`bg-${color}-50` のような動的クラス生成は Tailwind のスキャンに落ちるため禁止。カスタム `@theme` トークンは作らず、Tailwind 標準パレットをこのマップ経由でのみ使う）
- 新しい色用途（アクティブ状態など）が必要になったら `CATEGORY_STYLES` にフィールドを追加する。コンポーネント側で色クラスを直書きしない
- 決定した配色ルールは本ファイル §3 を正とし、CLAUDE.md からも参照させる

## 4. 現在地表示

- **ヘッダーパンくず（新設）**: メインエリア上部に薄いヘッダーバーを追加し、`大メニュー ＞ 画面名 ＞ タブ名` を常時表示。データソースは既存の `PAGE_DEFS` + `NAV_GROUPS`（新規のラベル二重管理はしない）。先頭にカテゴリ色のドットまたはバッジを付ける
- **サイドバー**: アクティブ項目を現行の黒背景から「カテゴリ色の `50` 背景 + `600` 左ボーダー + `700` 文字」へ変更。グループ見出しにもカテゴリ色の小ドットを付ける
- モバイル: パンくずはヘッダー内に画面名のみ（狭幅では大メニューを省略）

## 5. 着手順序（段階的・各ステップで人間確認）

### ステップ①: トップ画面（配色ルール確定）← 最初にここだけ実装
1. `globals.css`: ダークモードメディアクエリ削除・カテゴリ色トークン追加・フォント統一
2. `/admin/page.tsx` を新設: 白ベース・余白多めのハブ画面。3つの大メニューカード（カテゴリ色のアクセント + 配下メニュー一覧 + アイコン）を配置
3. リダイレクト変更: dev の `/` → `/admin`（ログイン後の遷移先は現行維持し、ロゴクリックで `/admin` へ戻れるようにする）
4. 配色ルールを本ファイルに確定として追記し、CLAUDE.md に参照を追加
5. **→ 人間確認。OKが出るまで②以降に進まない**

### ステップ②: 大メニュー反映（サイドバー・ヘッダー）
- `shell.tsx` のみ変更: グループ色ドット、アクティブ項目のカテゴリ色化、パンくずヘッダー新設
- 各画面の `page.tsx` は触らない（shell 一元化の恩恵を維持）

### ステップ③: 中メニュー（タブの統一）
- 共通 `TabNav` コンポーネントを新設し、カテゴリ色を props ではなく現在パスから自動解決
- 画面ごとに順次差し替え: dashboard → sales → billing → approval → cashflow → scan → partners → projects
- 1画面ずつコミットし、`read_page` で表示確認してから次へ

### ステップ④: 小メニュー・個別画面
- ピルサブナビ（sales の請求書生成内など）・KPIカード・テーブルを §2 の原則で順次調整
- 優先順はフィールドテストで露出が多い順: dashboard → schedules → scan → sales → billing

## 6. やらないこと・注意点

- 全画面一括変更はしない（①→確認→②→③の順を厳守）
- メニュー構成・URL・タブのパラメータキーは変更しない（お気に入り機能の保存URLを壊さないため）
- ドライバーアプリ（/driver）は今回のスコープ外（フィールドテスト後に同ルールで展開）
- ダッシュボードのグラフ配色は dataviz ルールで別途調整（カテゴリ色と混同させない）
- ビルド成果物のコミット禁止・コミット前の hibiki-security チェックは従来どおり
